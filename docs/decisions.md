# Decisions

Short log of product and technical decisions. Add new entries at the bottom.

| Decision | Why |
| --- | --- |
| Local-only, no deployment, no backend | Personal use by one learner; avoids privacy and cost concerns. |
| One active essay at a time; old ones go to an archive | Keeps the learner focused; nothing is ever deleted. |
| No timer | Requested by the learner's parent; routine is 15–20 minutes a day. |
| English-only UI and docs | Explicit requirement; original exam wording is English. |
| Only verified SEC questions (2024–2026 primary, 2023 additional) | Checked against official PDFs in `exam-papers/`; no invented content. |
| Official papers and marking schemes are kept locally in `exam-papers/`, which is git-ignored; the repository is public and the history was reset before publishing | Personal study use; PDFs and teacher sheets contain third-party copyrighted text that must not be republished. |
| Five steps with learner-controlled hint levels | Predictable guidance that can be faded as confidence grows. |
| Autosave plus a version on every step change; restore keeps an undo point | Reliable local data without a manual save habit. |
| Dexie/IndexedDB with explicit schema versions | Planned persistence; migrations must be additive. |
| JSON backup with `formatVersion` and strict validation | Browser storage can be cleared; restore must be safe. |
| Manual AI export (copy text, no network) | Learner decides what to share; no keys or transmission. |
| Self-check is the learner's own, using SEC criteria in plain words | Evidence-based practice, not authoritative marks. |
| Dependency-free editor on `contenteditable`, sanitised HTML subset | Paragraphs and minimal formatting without an editor library. CodeMirror was tried and dropped. |
| Facts-versus-reflection review is per paragraph, not per sentence | Essays are long; rating every sentence is impractical. Earlier per-sentence marks (`sentenceTags`) are ignored. |
| Revision planner is rule-based and runs on the device (no AI, no network) | The plan must be predictable, explainable, and private; the rules are simple enough to test. |
| Plan phases are anchored to the exam date: Build, Practise (up to 10 weeks), Exam mode (6 weeks), Light review (2 days) | Learning first, then application, then exam conditions; short plans shorten the early phases first. |
| Weekly study blocks are shared by confidence weight (weak 1.5, okay 1, strong 0.7), at least two a week per subject when there is room | More time where it is needed, without dropping any subject (spacing needs repeat visits). |
| Topic review uses fixed gaps of 1, 3, 7, 21, and 45 days; "Shaky" resets to 1 day | Simple spaced repetition the learner can understand; no scoring model. |
| Revision topic lists come from the NCCA specification, and the app only refers to past papers | Avoids invented content and keeps copyrighted paper text out of the app. Applied Mathematics strand 1 is not a study topic; it is assessed through the project and exam contexts. |
| Exam date defaults to 1 June and is editable | The SEC timetable is published later; a single date keeps the first version simple. |
| Backup `formatVersion` 2 adds revision data; restore merges it instead of replacing it | Restores never delete work: the newer settings win and each topic keeps its latest review. Version 1 files still load. |
| Done marks are cleared when the plan changes; topic progress is kept | Block positions change with the plan, while what the learner has learned does not. |
| Plan blocks are turned into timed steps with named past paper parts, chosen by a deterministic rotation | A teenager cannot act on "do revision"; naming the next question removes the guesswork. No randomness keeps the plan stable and testable. |
| Revision is split into a Today page for studying and a Calendar page for planning; unfinished blocks after the first are collapsed | While studying, the learner needs only the current block. Progress, phases, the weekly list, and settings are planning information and made the page about 5000px tall. Collapsing uses `hidden`, so typed answers are kept. |
| Russian is added as a skills-based subject with its own task writers, a writing check with profiles and typed practice sets of several kinds; tasks point to the real past papers by year | The topics, steps and prompts are in English and drive work on paper, aloud and in the learner's own text. Typed gap-fill, whole grammar texts, matching, word lists, culture quizzes and speaking prompts give instant checking or a clear self-check. The Higher papers, marking schemes and syllabus are in `exam-papers/sec/`, so tasks name the year and file; the app still holds no paper text. |
| Russian exam parts are named after the Higher papers and point to each year's question in our own words | The paper is the real example of the format: comprehension answered in English, a 30-mark grammar text, a 50-word essay with five facts, 140-word guided writing, and language awareness tasks. An earlier guess that comprehension is answered in Russian was wrong, so the steps now follow the marking scheme. The papers from 2019 to 2026 are available (2020 is kept but its Covid format is left out of the rotation), so each part has seven pointers. |
| The plan records the level of each subject, and Russian timed blocks name the exam parts of that level | Higher and Ordinary Russian have different written papers (guided writing, versus mix and match, short answers and extended writing), taken from the SEC 2027 arrangements. Topic lists stay shared apart from guided writing, which is Higher only. |
| Cyrillic is allowed only in the Russian data files named in `src/cyrillic.test.ts`, and nowhere else | The exercises have to be Russian for the learner to practise them. A test lists the allowed files so the English-only rule holds everywhere else. The sentences are original and were not checked by a Russian teacher, so treat a disagreement with the learner's teacher as the teacher being right. |
| Russian covers Higher Level only and the oral project (not picture sequences) | The learner sits Higher and chose the project for the 30-mark third oral section; the 2027 arrangements allow either. The Ordinary parts remain in the planner only because the plan records a level. |
| All Russian grammar texts, news items, lists and quizzes are original | The three texts first built on the teacher's sheets were rewritten in our own words before the repository went public. They were reviewed for Russian accuracy by a model, not by a teacher. |
| The setup form shows the modelling project only for Applied Mathematics and pre-selects only the first subject | The project is an Applied Mathematics assessment; other subjects should not carry it. |
| Past paper parts are mapped by hand to topics, with own-words summaries and no paper text | Questions must come from the official papers, never be invented, and copyrighted text must stay out of the app. Only years 2023 to 2026 are mapped because 2022 followed the old syllabus. |
| Practice problems are original, generated from a seed, and their answers are computed in code; they are never copied from exam papers | The learner needs tasks that can be checked on the spot, and exam content must not be invented or copied. A computed answer is always right and needs no network. |
| Diagrams are drawn as inline SVG from the same data that produces the answers; sketch tasks use a self-check list instead of an in-app drawing canvas | Pictures are how exam questions give data, and a computed picture can never disagree with its answer. Drawing happens on paper, which is what the exam needs, and a photo goes to the AI tool by hand, so there is no upload or canvas code to maintain. Every picture carries a text alternative. |
| The AI check is a prompt the learner copies by hand; the app does not call an AI | The project has no backend, API keys or network access. A prompt with the question, working and reference answers gives the same help without breaking that rule. |
| Recall prompts are written for the app and ask for ideas, not wording from any paper | Closed-book recall is the core study habit; the prompts must be correct and not tied to a textbook. |
| The app is renamed Leaving Cert Study Space; the essay pages are labelled "Essay ..." and Revision comes first in the navigation | The app grew from one essay trainer into a general Leaving Certificate study tool, so the old name and tagline no longer described it. Route paths stay the same. |
| The old name stays in the package name, the IndexedDB database name, the backup `app` value and the localStorage key | Renaming them would orphan saved data and make existing backups unreadable. They are internal identifiers the learner never sees. |
| An optional AI pack (`ai-pack/`): a tutor skill plus generated JSON with exercises and answer keys, instead of an MCP server or an in-app AI | Works with Claude, Copilot, ChatGPT or any chat with no backend, accounts or keys, and the app stays local-only. The JSON is generated from the app's own data and a test keeps it in sync. An MCP server would need a backend because the learner's progress lives in the browser. |
| Mathematics is a second maths subject beside Applied Mathematics, with Paper 1 and Paper 2 as the area of each topic and a `paper` field on every mapped question | The two maths papers are sat separately and the learner needs to know which to open. Descriptions read "2025 Paper 1 question 3", and the exam-mode block picks a whole year and paper. The same task writers serve both maths subjects. |
| Mathematics exam-mode wording comes from the 2027 arrangements: five of six Section A questions (30 marks) and three of four Section B questions (50 marks), per paper | The old specification stays for Mathematics in 2027. Applied Mathematics still says eight of ten. A `choiceNote` on the subject carries the difference. |
| Chemistry follows the new 2027 specification and maps only the two SEC sample papers; the old 2023 to 2026 papers are not mapped | Those papers test the old syllabus, so pointing the learner at them would mislead. Each paper part has a `label` ("Sample paper 1") instead of a year and paper, and the Practice Investigation (40%) stays outside the app because it is school-based coursework. |
| Biology follows the new 2027 specification like Chemistry, with 18 topics and numerical practice for the 14 topics that have calculations; the subject turns off the Formulae and Tables wording with `formulaeBooklet: false` | Biology has no formulae booklet, so the default task text would mislead. Topics such as classification, evolution, response and reproduction are descriptive and have recall prompts and paper pointers but no generator. |
| Physics topics follow the NCCA specification units, not a typical physics syllabus | The new specification leaves out capacitors, simple harmonic motion, gas laws, relativity and cosmology, so the planner, recall prompts and generators leave them out too. Astronomy is covered only as emission spectra and the Doppler shift, because the sample papers test that. |
| Practice problem generators for all maths subjects are reached through `problems/registry.ts` | `ProblemPanel` does not need to know which subject owns a topic id; topic id prefixes (`am-`, `mt-`, `ch-`, `bi-`, `ph-`) keep the ids apart. |
